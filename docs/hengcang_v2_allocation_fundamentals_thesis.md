## 1. 默认配置：60% 权益，其中海外 25%

### 1.1 新旧默认目标（目标 / 下限 / 上限，%）

| 资产桶 | v1 默认 | v2 默认 |
|---|---|---|
| 现金与债券 | 30 / 20 / 40 | 30 / 20 / 40 |
| 黄金 | 10 / 5 / 15 | 10 / 5 / 15 |
| 红利与价值 | 25 / 15 / 35 | **20 / 10 / 30** |
| 科技与成长 | 30 / 20 / 40 | **15 / 5 / 25** |
| 宽基权益 | 5 / 0 / 15 | **0 / 0 / 10** |
| 海外权益（新） | — | **25 / 15 / 35** |
| 其他 | 0 / 0 / 10 | 0 / 0 / 10 |
| 权益合计 | 60 | 60 |

代码：`src/domain/settings.ts` 的 `DEFAULT_ALLOCATION_BANDS`（v1 的值保留为 `V1_DEFAULT_ALLOCATION_BANDS`，供迁移判断）。

### 1.2 依据

固定比例、每季度再平衡、不计成本和税（详见 etf-trend `research/hengcang/README.md`）：

| 配置 | 2014-01 → 2023-12 年化 | 最大回撤 | 最长水下 | 2007 → 2023（含 2008）最大回撤 |
|---|---|---|---|---|
| v1 默认（全国内，科技 30%） | 6.8% | 34.0% | 5.6 年 | 52.6% |
| v2 默认（海外 25%） | 8.5% | 20.7% | 3.7 年 | 42.9% |

同样 60% 权益，把国内成长换成标普 500 后收益更高、回撤更小：海外仓位首先是分散，其次才是收益。

**数字偏乐观的地方**：海外部分事后看是美股最好的十年（人民币贬值每年还多贡献约 1.5 个点）；债券这十几年是牛市；真实持仓（港股互联网 ETF、单只股票）的波动比回测里的代理大。2008 年那样的危机里，60% 权益的组合仍可能跌 40% 以上。

### 1.3 海外权益桶不打分

`OVERSEAS_EQUITY` 是 `AssetBucket`，但不是 `ScorableAssetBucket`：Tushare 没有海外指数的估值和成分财报，硬凑评分只会制造假信号。它只受战略目标和区间约束，靠再平衡管理（偏离区间 → 再平衡参考里显示停止新增 / 等待确认）。

### 1.4 迁移 `drizzle/0004_v2_allocation_targets.sql`

- 组合现有的目标行**全部仍是 v1 默认值** → 改写为 v2 默认，并插入海外 25 / 15 / 35。设置页目前只读（只能改预留资金），所以现有组合基本都是这种情况。
- 目标**改过任何一个桶**（只可能是直接改了数据库）→ 原有目标一律不动，只插入海外 0 / 0 / 35 一行，不替用户做决定。
- 幂等：重复执行不会重复插入或二次改写（`tests/integration/v2-allocation-migration.test.ts` 用真实 drizzle migrator 在 v1 时代的数据库上验证）。

**升级后的直接影响**：科技与成长的上限从 40% 降到 25%。如果现有科技仓位超过 25%，该桶会显示「超配：停止新增，不强制卖出」，新增资金按目标流向海外、债券等低配桶，慢慢回到区间内。

## 2. 数据修复

### 2.1 财报每周增量刷新

v1 只在全量回填时拉 `fina_indicator`，日常刷新直接跳过。ROE（红利价值）和营收增长（科技成长）没有派生兜底，半年后撞上 180 天新鲜度闸门，基本面逐渐「失明」。

v2（`src/server/automatic-data-refresh-service.ts`）：

- `fundamentalsRefreshMode`：`FULL_BACKFILL=true` → 全量；距上次成功 ≥ 7 天（`FUNDAMENTALS_REFRESH_INTERVAL_DAYS`）或从未成功 → 增量；否则跳过。
- 增量窗口 15 个月（`FUNDAMENTALS_INCREMENTAL_WINDOW_MONTHS`），足够覆盖「最新一期 + 约一个季度前」两期对照。
- 状态单独记在 `data_source_status` 的 `tushare-fina` 行；失败不记成功，下一轮自动重试。
- 分红历史（分红稳定性）同样每周一次（原来每 6 小时）。

每周轮询比按披露日历精确调度简单，最多晚一周拿到新财报；披露日历驱动留作后续（§6）。

### 2.2 增量只重算最近的日期

`selectAggregationDates`：增量模式为「上次桶级汇总前 30 天以来」的日期生成汇总。
- 更早的历史不动：窗口只有 15 个月，重算窗口前部的历史日期时，部分成分股当时的最新财报落在窗口外，低覆盖率的结果会覆盖全量回填时算好的历史行。
- 最近 30 天要重算（2026-10-28 复查修正）：公告日在上次汇总之前、晚几天才进入 Tushare 的财报在财报季很常见，只算新日期就永远并不进来。

每个桶级汇总行在 `metadataJson` 里记下按权重占主导的报告期（`reportPeriod`）和它占有效权重的比例（`reportPeriodShare`），体检据此找「上一期」（§3.2）。

每家公司取评价日已经公告的最新一份财报。同一天发了两份（年报和一季报常在 4 月底一起发）取报告期新的那份；Tushare 对修正过的财报会返回修正前后两条，只留修正后的（`update_flag = 1`）。之前这两种情况取哪份看数据返回顺序：2026-10-30 按库里的顺序离线重算时，长江电力取成了 2025 年报，它的权重正好在中位数上，上证50 盈利同比从 +28.74% 变成 +6.17%。财报刷新状态在数据入库之后才记成功（中途崩溃不会让下一次刷新白白跳过 7 天）。

### 2.3 派生口径单独存

v1 把「价格 ÷ PE 推出来的盈利增长」和「成分股财报汇总的盈利增长」写进同一个指标（`EARNINGS_GROWTH` / `INDEX_EARNINGS_GROWTH`），取数时每个日期跨来源只挑一行，分位数历史里交替出现两种定义。

v2：派生值写到 `EARNINGS_GROWTH_DERIVED` / `INDEX_EARNINGS_GROWTH_DERIVED`（`src/metrics/catalog.ts`），只作参考展示，不进体检。`drizzle/0005_v2_derived_growth_keys.sql` 把已有的 `provider = 'tushare-derived'` 行改到新指标名下。

## 3. 基本面：体检 + 熔断

### 3.1 为什么不再按分位数打分

v1 的基本面分 = 当前值在自己近 3–5 年历史里的分位，以 30% 权重进入配置吸引力分，低于 35 触发熔断。分位是相对值：

- 连续几年变差之后，平庸的增长也能排到高分位，熔断反而解除；
- 繁荣之后的正常放缓却可能触发熔断；
- 增长率受基数效应影响很大（疫情前后尤其明显）。

v2 只回答一个问题：**基本面在恶化吗？** 用看得懂的绝对规则判断。恶化 → 暂停新增、重新评估逻辑；没有恶化 → 不加分也不减分。

### 3.2 体检规则（`src/domain/scoring/health-check.ts`）

| 资产桶 | 检查项（任一不通过即「恶化」） |
|---|---|
| 红利与价值 | 盈利同比最近两期都为负；分红稳定性 < 60 |
| 红利与价值（基金拿不到成分财报，有手工基本面判断时） | 手工基本面判断 < 35（替代上面两项） |
| 科技与成长 | 盈利同比最近两期都为负；营收同比最近两期都为负 |
| 宽基权益 | 指数盈利同比最近两期都为负 |
| 黄金 | 不适用（见 §3.4） |

- 桶级的盈利、营收同比是成分股增速的**加权中位数**（按指数权重，「典型公司的增速」），ROE 仍是去极值后的加权均值。2026-10-30 用真实数据复查时发现，加权均值会被小基数公司的暴涨拉高好几倍（创业板指成分股 95 分位 +1386%：加权均值 +128%，加权中位数 +42%；沪深300 +44% 对 +13%），多数公司下滑时均值仍可能为正，体检就看不到恶化。改用中位数后，「为负」的意思是指数里一半以上的权重盈利同比在下降。
- 「最近两期」= 最新值，以及上一个报告期的值（两期最多相隔约两个季度）。只有一期为负不算恶化。
  - 上一个报告期 = 比最新一点的主导报告期早的最近一期。不能按公告日的固定间隔取：半年报截止 8/31、三季报截止 10/31 只隔 61 天，原来的「相隔 80–200 天」在三季报季会拿三季报去比一季报（2026-10-28 复查修正）。
  - 那一期有很多个点，取主导报告期占比最高的（相差不到 2 个百分点的取较新的）。财报季里紧挨着最新点的前几天，新财报已经占了不少权重，拿它当上一期等于新财报和自己比：2026-10-30 沪深300 的上一期原来取到 10-29 的 +18.18%（那天三季报已占四成多），纯半年报时是 +26.17%。半年报为正、三季报为负时，这个混合点可能已经转负，会把一期为负误判成连续两期为负、提前暂停新增（2026-10-30 修正）。
  - 旧数据没有报告期标记时退回「相隔 80–200 天」，没有占比时取那一期最近的点；升级后做一次全量回填（§5）就都有了。
  - 资产评分页的体检明细里，每个点都标出以哪期财报为主（例如「2026 半年报为主」）。
- 手工基本面判断（基金拿不到成分财报时的兜底）只在新鲜时替代自动体检：超过 180 天的旧判断不再盖住自动规则发现的恶化。
- 每项结果为 `OK` / `BREACH` / `MISSING`。缺数据、超过 180 天未更新、缺少约一个季度前的对照值都算 `MISSING`。
- 汇总：有任一 `BREACH` → `DETERIORATING`；全部 `MISSING` → `UNKNOWN`；否则 `HEALTHY`；黄金 → `NOT_APPLICABLE`。

参数（`default-config.json` v6）：

```json
"healthCheck": { "previousReportMinDays": 80, "previousReportMaxDays": 200, "dividendStabilityFloor": 60 },
"thresholds": { "fundamentalCircuitBreaker": 35, ... }
```

`fundamentalCircuitBreaker` 现在只用于手工基本面判断的下限。

### 3.3 怎么进入状态机（`src/domain/scoring/engine.ts`）

```text
配置吸引力分 = 70% × 便宜程度 + 30% × 趋势
```

v5 是 50% 便宜程度 + 30% 基本面 + 20% 趋势；去掉基本面后按原比例归一（0.5 : 0.2 ≈ 0.7 : 0.3）。基本面的分位分仍会计算，只在界面上展示，不进分数。

状态判定顺序（`applyRiskRules`）：

1. 体检 `DETERIORATING`（黄金除外）→ `REASSESS_THESIS`，即时生效，不走三日确认；原因里写明哪条规则、哪两期数值。
2. 单股 / 主题硬上限违规或桶超配 → `OVERWEIGHT`（即时）。
3. 分数缺失或可信度 LOW → `LOW_CONFIDENCE`（即时）。
4. 按分数得到普通状态；可信度 MEDIUM 时不输出强增配 / 减仓。
5. 体检 `UNKNOWN`（黄金除外）→ 最多输出「小幅增配」：无法确认没有恶化，就不放大仓位。

另外，整根支柱（便宜程度或趋势）缺失时按 `LOW_CONFIDENCE` 处理（体检不通过和超配优先）。

手工兜底评分（`/api/scores/manual`）不再填 0–100 的基本面分，改为选择体检结果：正常 / 恶化 / 数据不足。

界面：资产评分页显示体检结果和逐项明细（规则、两期数值和日期、缺数据原因）；仪表盘和评分说明浮层显示体检状态。规范案例见 `tests/unit/scoring.test.ts`（Case A 77 分强增配、Case C 便宜但体检不通过 → 重新评估、Case D 黄金 49.5 分持有）。

### 3.4 黄金

- 黄金没有经营基本面：体检为 `NOT_APPLICABLE`，不会触发 `REASSESS_THESIS`，也不受「数据不足 → 最多小幅增配」的封顶。
- 宏观支持度（实际利率、美元、资金流）**只展示**。v1.2 的「宏观逆风 → 停止新增」规则（`goldMacroHeadwind`）已删除：2022 年以后各国央行大量购金，美国实际利率升到十几年高位而金价大涨，旧关系脱钩，按旧规则会恰好错过这段行情。
- 黄金的状态只由配置吸引力分（便宜程度 + 趋势）、超配和可信度决定。
- 央行购金没有自动数据源；需要时按世界黄金协会每季度的《黄金需求趋势》手工录入（一年 4 个数），同样只展示。

`docs/hengcang_gold_model_revision_v1_2.md` 保留作历史记录，其中宏观闸门部分以本节为准。

## 4. 持仓级投资逻辑、失效条件与事件日志

### 4.1 为什么消息不打分

把新闻自动打成分数噪音大、没有可回测的历史，被新闻牵着走是个人投资者最常见的亏法。财报要季度末后 1–4 个月才公布，等财报里的增长转负，价格往往已经跌了很多，体检熔断那时才触发，太晚。

v2 的做法：**事先写下「为什么持有」和「什么情况说明逻辑失效」，消息只用来对照这几条事实。** 消息怎么进来：§7 的 AI 新闻监控每天自动搜索并对照判断，不用你看网页、录消息；AI 没搜到的可以手工补记。

### 4.2 规则（`src/domain/thesis.ts`、`src/server/thesis-service.ts`）

- **谁必须写**：单一个股和主题 ETF（`isSingleStock` / `isThematicEtf`）。它们的风险来自具体公司或行业的消息；宽基、债券、黄金由配置纪律管住，可写可不写。
- **投资逻辑**：一段话（≤ 2000 字）。**失效条件**：可验证的事实，建议 3–5 条，最多 8 条，每条 ≤ 200 字。
- **记录消息（NEWS）**：日期（不能晚于今天）+ 发生了什么 + 来源链接（只允许 http/https）+ 可选「对应哪条失效条件」。
  - 对应到某条 → 该条变为「已触发」，**该持仓暂停新增**，写一条 WARNING 信号。
  - 不对应 → 只记录。
- **写复核（REVIEW）**：
  - 对应已触发的条件 → 解除（回到有效），写一条 INFO 信号。
  - 不对应条件 → 定期复核。
- **季度复核**：自上次复核（没有则自写下逻辑起）满 90 天，提示「季度复核到期」。
- **已触发的条件锁定**：不能删除也不能改写，必须先写复核解除。否则改几个字就能绕过暂停。
- 删除持仓时，投资逻辑、失效条件和事件一并删除。

暂停新增是**持仓级**的：不改变所在资产桶的评分和状态。科技与成长可以仍是「可增配」，但新增资金不投给逻辑待复核的那只持仓。系统不执行交易，「暂停」是给人看的纪律提醒。

### 4.3 在哪里看到

- **持仓与风险**页：新增「投资逻辑」列（逻辑完好 / 季度复核到期 / 逻辑待复核：暂停新增 / 未写投资逻辑），点进 `/holdings/[id]`。
- **`/holdings/[id]`**：编辑投资逻辑和失效条件、AI 新闻监控（§7）、手工补记消息、对已触发的条件写复核、定期复核、完整事件日志（含来源链接和记录时间）。
- **仪表盘**：「投资逻辑提醒」卡片常驻显示需要处理的持仓（暂停新增优先，其次复核到期，最后是集中持仓没写逻辑），处理完才消失。「最新信号」只显示最近 5 条，触发信号会被后来的评分信号挤掉，所以另做了常驻提醒。

### 4.4 数据与接口

迁移 `drizzle/0006_v2_holding_thesis.sql` 只新增三张表：

| 表 | 内容 |
|---|---|
| `holding_theses` | 每个持仓最多一份（`holding_id` 唯一），随持仓级联删除 |
| `thesis_breakers` | 失效条件：`status`（ACTIVE / TRIGGERED）、`triggered_at`、`triggered_by_event_id`、`last_reviewed_at` |
| `thesis_events` | 事件：`kind`（NEWS / REVIEW / DISMISS）、`origin`（MANUAL / AI，§7）、`occurred_on`、`summary`、`source_url`、`breaker_id`（条件删除时置空）、`recorded_at` |

接口：

- `GET /api/portfolio/holdings/:id/thesis`：逻辑、条件、事件、状态、是否需要写、是否到期。
- `PUT /api/portfolio/holdings/:id/thesis`：`{ thesis, breakers: [{ id?, description }] }`。带 id 的是修改 / 保留，不带 id 的是新增，没提交的会删除；改动或删除已触发的条件返回 409 `BREAKER_TRIGGERED`。
- `POST /api/portfolio/holdings/:id/thesis/events`：`{ kind: "NEWS", occurredOn, summary, sourceUrl?, breakerId? }` 或 `{ kind: "REVIEW", occurredOn, summary, breakerId? }`。还没写逻辑返回 409 `THESIS_NOT_FOUND`；条件不属于这份逻辑返回 422 `UNKNOWN_BREAKER`。

### 4.5 失效条件示例

- **港股互联网 ETF**：出现新的平台监管整顿；龙头营收连续两个季度负增长；回购明显收缩。
- **先导智能**：锂电设备行业资本开支同比下滑超过 30%；最大客户订单明显缩减；毛利率连续两个季度下滑。

写法要点：写可验证的事实（谁、什么指标、多大幅度），不写「感觉不好了」「跌太多了」这类价格描述。

## 5. 升级步骤

1. 停掉开发服务器和 `pnpm worker`，**先备份数据库**：`cp data/hengcang.db data/hengcang.before-v2.db`。
2. `git checkout main && git pull`，然后 `pnpm install`、`pnpm db:migrate`（依次执行 0004–0007）。
3. 运行一次 `pnpm data:refresh`（或页面「一键自动刷新评分」）：升级后第一次刷新会做财报增量刷新，并用 v6 规则重算评分。
4. 打开「设置」核对战略仓位应为 v2 默认值（海外权益 25%）。如果显示海外 0%，说明数据库里的目标改过，迁移没有覆盖，需要同样直接改库。
5. 在「持仓与风险」里给单一个股和主题 ETF 写投资逻辑和失效条件（可以先让 AI 起草）。
6. 在 `.env.local` 配置 `DEEPSEEK_API_KEY` 并重启，开启 AI 新闻监控（§7.5）；常驻 `pnpm worker` 就会每天自动扫描。
7. 做一次全量回填：`FULL_BACKFILL=true pnpm data:refresh`。它会按 2026-10-28、10-30 修正后的规则重算历史上的桶级财报汇总（增长率用加权中位数、同一天两份财报取新的一期、修正过的财报只留修正后的），并补上报告期标记和占比，体检才能按报告期找「上一期」（§3.2）。要在固定 IP 的机器上跑：Tushare 一个 Token 最多同时用 10 个 IP。

要回到 v1：停服务，`git checkout 8ef4160`（v2 合并前的 main），把备份文件拷回 `data/hengcang.db`。

## 6. 没做的和后续

- **按披露日历刷新财报**：现在是每周轮询，最多晚一周。
- **历史成分权重**：历史汇总用当前成分股，有幸存者偏差；应改用 `index_weight` 的历史快照。
- **换代理**：红利价值改中证红利（现为上证 50）；科技成长按真实持仓拆（港股互联网用恒生互联网类指数）；单只股票用它自己的财报做体检。在此之前，单股和港股互联网的风险主要靠 §4 的失效条件。
- **验证**：体检和失效条件没有样本外回测，定位是纪律规则，不是收益来源；估值和趋势打分在样本外验证之前只宜做小幅偏离。

## 7. AI 新闻监控（2026-10-19 追加）

### 7.1 为什么要做

要人去看网页、再把消息录进系统不现实，§4 的失效条件会形同虚设。DeepSeek 在 2026-10-17 开放了网页搜索（Search）和网页抓取（Fetch）接口，与对话模型共用一个 API Key，价格低、中文覆盖好、国内直连。接口细节以官方文档为准（api-docs.deepseek.com），客户端在 `src/providers/deepseek/index.ts`。

### 7.2 流程（`src/server/news-watch-service.ts`，规则在 `src/domain/news-watch.ts`）

每份投资逻辑每天扫描一次（worker 每 30 分钟检查一次，距上次扫描满 20 小时才扫；详情页也可以「立即检查新闻」）：

1. **生成搜索词**：模型根据投资逻辑和失效条件生成 3–6 个搜索词并缓存；逻辑或条件改了才重新生成。模型失败时先用「持仓名称 + 条件」兜底，下一轮再试。
2. **搜索**：每个搜索词加 `after:<30 天前>`，取 10 条并带正文。按链接去重（去掉跟踪参数），同一标题被多家网站转载只留一条；看过的链接和标题不再判断；超过 30 天的丢掉；按 `rerank_score` 取前 20 条。
3. **初筛**：模型按摘要逐条判断「可能触发 / 相关 / 无关」。条件以 B1、B2 编号交给模型，答出列表外的编号作废；已触发的条件不再交给模型。
4. **复核**：「可能触发」的前 3 篇带正文复核（搜索结果没带正文就调 Fetch 抓取）。模型给出是否已经发生、置信度、事件日期，并逐字摘录一句原文作为证据。
5. **决定**：下表五条同时满足才自动触发，否则标为「可能触发」等你确认。

| 自动触发需要 | 不满足时 |
|---|---|
| 复核结论为「已经发生」且高置信 | 可能触发 |
| 证据能在原文里逐字找到（忽略空白、标点、全半角差异） | 可能触发 |
| 文章有发布日期且在最近 30 天内；模型给出的事件日期也在 30 天内（日期不明的一律不自动触发） | 可能触发 |
| 来源权威度 ≥ 2（搜索接口给出的 -1–4 分，-1 为未知） | 可能触发 |
| 条件尚未触发（同一轮已被另一篇触发的，后面的只算相关） | 相关 |
| 你对这条条件写过复核或撤销过误判：事件必须晚于那一天，且有明确的事件日期 | 不晚于那一天的只算相关；日期不明的为可能触发 |
| 事件晚于写下（或改写）这条条件的那一天 | 可能触发（多半是写下时就已成立，该改写条件） |

另外每条条件最多留一条待确认的「可能触发」：同一事实常被多家转载，其余的只算相关。

「复核 / 撤销之后」一条是 2026-10-28 复查后加的：之前撤销误判或写完复核后，同一条新闻换个网站转载会让条件反复触发。另外，模型初筛的回复格式不对时，这一轮直接失败、下一轮重试，不会把文章当「无关」标成看过；删掉或改写条件时，它名下待确认的「可能触发」一并忽略。

自动触发和手工记录走同一条路径：条件变为「已触发」，该持仓暂停新增，写一条 WARNING 信号（注明是 AI 判断），仪表盘常驻提醒。

**用真实接口试跑（2026-10-28）**：Search、Fetch、对话（关闭思考 / 低强度思考）的请求和返回格式都和客户端一致，单次搜索约 1 秒、抓取约 4 秒、对话约 1 秒。拿先导智能和港股互联网 ETF 跑通了「AI 起草 → 保存 → 检查新闻」，各看了 20 篇当月新闻。试跑发现并修正了三处：
- 起草的失效条件里出现「指数前十大权重合计超过 70%」这种写下时就已成立的事实，第一轮扫描就把持仓暂停了。现在起草提示要求只写「逻辑被破坏」的信号、写下时尚未发生、ETF 写重仓公司而不是产品细节；即使条件写得不好，早于写下那天的事件也只标「可能触发」。
- 同一篇稿子被五六家网站转载，占满候选名额：现在按标题去重，看过的标题不再判断。
- 来源名偶尔是十六进制编码（如 `e8af81e588b8e697b6e68aa5` = 证券时报）：现在按 UTF-8 解码，没有来源名时用链接的域名。

### 7.3 你需要做的

- **自动触发的**：点开原文看一眼。属实就写复核（和以前一样）；误判就点「误判，撤销」——条件恢复，记一条「撤销误判」事件（不算复核，不会重置季度复核时间），写 INFO 信号。
- **可能触发的**：一键「确认触发」或「忽略」。仪表盘「投资逻辑提醒」会显示「AI 发现可能触发：待确认」。
- **还没写逻辑的持仓**：可以点「让 AI 起草」。草稿只填进编辑框，改好再保存。
- 「手工补记一条消息」保留，用来补 AI 没搜到的消息。

### 7.4 安全与隐私

- 发给 DeepSeek 的只有持仓名称、代码、类型、投资逻辑和失效条件；不发金额、仓位或账户信息。
- 新闻是不可信输入。系统提示要求模型把新闻当数据、忽略其中的指令；模型的输出只能指向列表里的条件，证据必须能在原文里找到，链接只来自本次搜索结果。网页里夹带的文字没法让系统凭空触发，更没法卖出——最坏情况是一次误判的「暂停新增」，可以一键撤销。
- API Key 只放在 `.env.local`，不写日志、不进数据库。401（Key 无效）和 402（余额不足）只显示固定说明，整轮停止，下一轮重试；408 / 429 / 5xx 按官方建议等待后重试。

### 7.5 配置、运行与费用

- `.env.local`：`DEEPSEEK_API_KEY=…`（必填）；`DEEPSEEK_MODEL` 默认 `deepseek-flash`，可改 `deepseek-v4-pro`。没配置时一切照旧，新闻监控显示「未配置」。
- 运行：常驻 `pnpm worker` 时每天自动扫描；`pnpm news:scan` 扫描到期的逻辑，`pnpm news:scan --force` 立即扫描全部。
- 费用：Search、Fetch 各按每 1000 次成功请求 5 元（2026-11-01 起计费；失败和空结果不计费），与对话 token 共用 DeepSeek 账户余额。每只持仓每天约 3–6 次搜索、0–3 次抓取、2–5 次模型调用：搜索和抓取每只每月不到 1 元，模型按 token 计费，实际花费在 DeepSeek 控制台查看。
- 「数据状态」页的 `deepseek-news` 一行显示最近一次扫描的结果和问题。

### 7.6 数据

迁移 `drizzle/0007_v2_news_watch.sql` 只做加法：

- 新表 `news_items`：看过的每篇文章（链接、标题、来源、发布日、摘要、判断结果、对应条件、证据、权威度、关联事件、处理状态）。同一份逻辑同一链接只判断一次；「无关」的只为去重保留 60 天。
- `holding_theses` 加 `news_queries_json`、`news_queries_basis`、`news_scanned_at`。
- `thesis_events` 加 `origin`（MANUAL / AI）；`kind` 新增 `DISMISS`（撤销误判）。

### 7.7 局限

- 搜索引擎没收录的消息会漏（付费终端、部分公告 PDF），重要的仍可手工补记。
- 文章日期偶尔缺失或不准：日期不明的不会自动触发。
- 模型会判断错：所以自动触发只「暂停新增」、可一键撤销，不产生任何卖出建议。
- 没有历史回测：这是纪律工具，不是收益来源。

## 8. 评分计算复查（2026-10-31，模型版本 7）

用确定性合成数据跑完整的「拉数 → 入库 → 汇总 → 评分」，在测试里按规格独立重算便宜程度、趋势、配置吸引力分并逐项对比（`tests/integration/refresh-pipeline-accuracy.test.ts`），发现并修了下面几处。前四处都会让「便宜程度」（占配置吸引力分 70%）失真。

| 问题 | 影响 | 修复 |
|---|---|---|
| 历史分位用全部历史，没有 5 年窗口 | 用得越久窗口越长，和规格 §3.1「5 年」不符 | 只和评估日前 5 年内的历史比（`history.windowYears = 5`，不含正好 5 年前那天） |
| 估值序列入库频率不一：全量回填是月末快照，之后每天刷新都加一点 | 用一年后近一年的点占八成，「5 年分位」变成「近一年分位」。拿 ETF 价格模拟：沪深300 同一个值，月末口径 68 分位，月末 + 一年日频只有 15 | 估值、财报、宏观类按自然月取样（每月最后一点）；只有一直按交易日入库的行情派生特征（动量、距 MA200、金价位置）逐日算 |
| PE / PB 逐日挑来源：有官方指数估值（index_dailybasic）的日子用官方，没有就用成分股汇总 | 官方只拉了当月，于是当前值是官方口径、历史是汇总口径（汇总剔除亏损股，口径不同），分位系统性偏 | 一条序列只用一个来源：在仍在更新的来源里取历史最长的，一样长取优先级高的（官方）；手工覆盖仍逐日生效。全量回填改为拉 5 年官方估值、增量拉 1 年 |
| 全量回填只拉 5 年行情 | 6 个月动量、MA200 要往前看 126 / 200 个交易日，5 年窗口里只有 4.2–4.5 年的值 | 全量回填行情多拉一年（估值汇总的采样日仍是 5 年） |
| PEG 只取 PE 和增速恰好同一天都有的点 | 历史又稀又不均匀 | 每个 PE 点配日期不晚于它的最新增速（最多旧 200 天） |
| 分位按「≤ 当前」计数（Code Review L4） | 「越低越好」的指标在历史最便宜时也只有约 98 分，两个方向不对称 | 中位秩：(更低的个数 + 相等个数 / 2) / 样本数 |
| 5 年没分过红的成分股直接剔除 | 指数分红稳定性偏高，长期不分红的公司越多越看不出来 | 有分红记录但 5 年无现金分红按规格得 10 分；完全没有记录（新股、缺数据）才不算 |
| 回测「夏普」没扣无风险利率 | 绝对值偏高 | 表头改为「收益/波动比」并注明 |

**要做的**：升级后做一次全量回填（§5 第 7 步）。在那之前，官方估值只有几个月，PE / PB 会继续用成分股汇总的 5 年历史（口径一致、按月取样），分数已经比修复前准确；回填后自动换成官方口径。修复前每天刷新攒下的日频点不用删，按月取样后不再带偏。
