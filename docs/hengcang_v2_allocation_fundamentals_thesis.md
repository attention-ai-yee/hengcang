## 1. 默认配置：60% 权益，其中海外 25%

### 1.1 新旧默认目标（目标 / 下限 / 上限，%）

| 资产桶 | v1 默认 | v2 默认 |
|---|---|---|
| 现金与债券 | 30 / 20 / 40 | 30 / 20 / 40 |
| 黄金 | 10 / 5 / 15 | 10 / 5 / 15 |
| 红利与价值 | 25 / 15 / 35 | **20 / 10 / 30** |
| 科技与成长 | 30 / 20 / 40 | **15 / 5 / 25** |
| 宽基权益 | 5 / 0 / 15 | **0 / 0 / 10** |
| 海外权益（新） | — | **25 / 15 / 35** |
| 其他 | 0 / 0 / 10 | 0 / 0 / 10 |
| 权益合计 | 60 | 60 |

代码：`src/domain/settings.ts` 的 `DEFAULT_ALLOCATION_BANDS`（v1 的值保留为 `V1_DEFAULT_ALLOCATION_BANDS`，供迁移判断）。

### 1.2 依据

固定比例、每季度再平衡、不计成本和税（详见 etf-trend `research/hengcang/README.md`）：

| 配置 | 2014-01 → 2023-12 年化 | 最大回撤 | 最长水下 | 2007 → 2023（含 2008）最大回撤 |
|---|---|---|---|---|
| v1 默认（全国内，科技 30%） | 6.8% | 34.0% | 5.6 年 | 52.6% |
| v2 默认（海外 25%） | 8.5% | 20.7% | 3.7 年 | 42.9% |

同样 60% 权益，把国内成长换成标普 500 后收益更高、回撤更小：海外仓位首先是分散，其次才是收益。

**数字偏乐观的地方**：海外部分事后看是美股最好的十年（人民币贬值每年还多贡献约 1.5 个点）；债券这十几年是牛市；真实持仓（港股互联网 ETF、单只股票）的波动比回测里的代理大。2008 年那样的危机里，60% 权益的组合仍可能跌 40% 以上。

### 1.3 海外权益桶不打分

`OVERSEAS_EQUITY` 是 `AssetBucket`，但不是 `ScorableAssetBucket`：Tushare 没有海外指数的估值和成分财报，硬凑评分只会制造假信号。它只受战略目标和区间约束，靠再平衡管理（偏离区间 → 再平衡参考里显示停止新增 / 等待确认）。

### 1.4 迁移 `drizzle/0004_v2_allocation_targets.sql`

- 组合现有的目标行**全部仍是 v1 默认值** → 改写为 v2 默认，并插入海外 25 / 15 / 35。设置页目前只读（只能改预留资金），所以现有组合基本都是这种情况。
- 目标**改过任何一个桶**（只可能是直接改了数据库）→ 原有目标一律不动，只插入海外 0 / 0 / 35 一行，不替用户做决定。
- 幂等：重复执行不会重复插入或二次改写（`tests/integration/v2-allocation-migration.test.ts` 用真实 drizzle migrator 在 v1 时代的数据库上验证）。

**升级后的直接影响**：科技与成长的上限从 40% 降到 25%。如果现有科技仓位超过 25%，该桶会显示「超配：停止新增，不强制卖出」，新增资金按目标流向海外、债券等低配桶，慢慢回到区间内。

## 2. 数据修复

### 2.1 财报每周增量刷新

v1 只在全量回填时拉 `fina_indicator`，日常刷新直接跳过。ROE（红利价值）和营收增长（科技成长）没有派生兜底，半年后撞上 180 天新鲜度闸门，基本面逐渐「失明」。

v2（`src/server/automatic-data-refresh-service.ts`）：

- `fundamentalsRefreshMode`：`FULL_BACKFILL=true` → 全量；距上次成功 ≥ 7 天（`FUNDAMENTALS_REFRESH_INTERVAL_DAYS`）或从未成功 → 增量；否则跳过。
- 增量窗口 15 个月（`FUNDAMENTALS_INCREMENTAL_WINDOW_MONTHS`），足够覆盖「最新一期 + 约一个季度前」两期对照。
- 状态单独记在 `data_source_status` 的 `tushare-fina` 行；失败不记成功，下一轮自动重试。
- 分红历史（分红稳定性）同样每周一次（原来每 6 小时）。

每周轮询比按披露日历精确调度简单，最多晚一周拿到新财报；披露日历驱动留作后续（§6）。

### 2.2 增量只汇总新日期

`selectAggregationDates`：增量模式只为「上次桶级汇总之后」的日期生成新汇总。窗口只有 15 个月，若重算窗口前部的历史日期，部分成分股当时的最新财报落在窗口外，低覆盖率的结果会覆盖全量回填时算好的历史行。

### 2.3 派生口径单独存

v1 把「价格 ÷ PE 推出来的盈利增长」和「成分股财报汇总的盈利增长」写进同一个指标（`EARNINGS_GROWTH` / `INDEX_EARNINGS_GROWTH`），取数时每个日期跨来源只挑一行，分位数历史里交替出现两种定义。

v2：派生值写到 `EARNINGS_GROWTH_DERIVED` / `INDEX_EARNINGS_GROWTH_DERIVED`（`src/metrics/catalog.ts`），只作参考展示，不进体检。`drizzle/0005_v2_derived_growth_keys.sql` 把已有的 `provider = 'tushare-derived'` 行改到新指标名下。

## 3. 基本面：体检 + 熔断

### 3.1 为什么不再按分位数打分

v1 的基本面分 = 当前值在自己近 3–5 年历史里的分位，以 30% 权重进入配置吸引力分，低于 35 触发熔断。分位是相对值：

- 连续几年变差之后，平庸的增长也能排到高分位，熔断反而解除；
- 繁荣之后的正常放缓却可能触发熔断；
- 增长率受基数效应影响很大（疫情前后尤其明显）。

v2 只回答一个问题：**基本面在恶化吗？** 用看得懂的绝对规则判断。恶化 → 暂停新增、重新评估逻辑；没有恶化 → 不加分也不减分。

### 3.2 体检规则（`src/domain/scoring/health-check.ts`）

| 资产桶 | 检查项（任一不通过即「恶化」） |
|---|---|
| 红利与价值 | 盈利同比最近两期都为负；分红稳定性 < 60 |
| 红利与价值（基金拿不到成分财报，有手工基本面判断时） | 手工基本面判断 < 35（替代上面两项） |
| 科技与成长 | 盈利同比最近两期都为负；营收同比最近两期都为负 |
| 宽基权益 | 指数盈利同比最近两期都为负 |
| 黄金 | 不适用（见 §3.4） |

- 「最近两期」= 最新值，以及与它相隔 80–200 天的上一个值（约一个季度前）。桶级汇总随成分股陆续披露而更新，按日期间隔取上一期比按点数取更稳。只有一期为负不算恶化。
- 每项结果为 `OK` / `BREACH` / `MISSING`。缺数据、超过 180 天未更新、缺少约一个季度前的对照值都算 `MISSING`。
- 汇总：有任一 `BREACH` → `DETERIORATING`；全部 `MISSING` → `UNKNOWN`；否则 `HEALTHY`；黄金 → `NOT_APPLICABLE`。

参数（`default-config.json` v6）：

```json
"healthCheck": { "previousReportMinDays": 80, "previousReportMaxDays": 200, "dividendStabilityFloor": 60 },
"thresholds": { "fundamentalCircuitBreaker": 35, ... }
```

`fundamentalCircuitBreaker` 现在只用于手工基本面判断的下限。

### 3.3 怎么进入状态机（`src/domain/scoring/engine.ts`）

```text
配置吸引力分 = 70% × 便宜程度 + 30% × 趋势
```

v5 是 50% 便宜程度 + 30% 基本面 + 20% 趋势；去掉基本面后按原比例归一（0.5 : 0.2 ≈ 0.7 : 0.3）。基本面的分位分仍会计算，只在界面上展示，不进分数。

状态判定顺序（`applyRiskRules`）：

1. 体检 `DETERIORATING`（黄金除外）→ `REASSESS_THESIS`，即时生效，不走三日确认；原因里写明哪条规则、哪两期数值。
2. 单股 / 主题硬上限违规或桶超配 → `OVERWEIGHT`（即时）。
3. 分数缺失或可信度 LOW → `LOW_CONFIDENCE`（即时）。
4. 按分数得到普通状态；可信度 MEDIUM 时不输出强增配 / 减仓。
5. 体检 `UNKNOWN`（黄金除外）→ 最多输出「小幅增配」：无法确认没有恶化，就不放大仓位。

另外，整根支柱（便宜程度或趋势）缺失时按 `LOW_CONFIDENCE` 处理（体检不通过和超配优先）。

手工兜底评分（`/api/scores/manual`）不再填 0–100 的基本面分，改为选择体检结果：正常 / 恶化 / 数据不足。

界面：资产评分页显示体检结果和逐项明细（规则、两期数值和日期、缺数据原因）；仪表盘和评分说明浮层显示体检状态。规范案例见 `tests/unit/scoring.test.ts`（Case A 77 分强增配、Case C 便宜但体检不通过 → 重新评估、Case D 黄金 49.5 分持有）。

### 3.4 黄金

- 黄金没有经营基本面：体检为 `NOT_APPLICABLE`，不会触发 `REASSESS_THESIS`，也不受「数据不足 → 最多小幅增配」的封顶。
- 宏观支持度（实际利率、美元、资金流）**只展示**。v1.2 的「宏观逆风 → 停止新增」规则（`goldMacroHeadwind`）已删除：2022 年以后各国央行大量购金，美国实际利率升到十几年高位而金价大涨，旧关系脱钩，按旧规则会恰好错过这段行情。
- 黄金的状态只由配置吸引力分（便宜程度 + 趋势）、超配和可信度决定。
- 央行购金没有自动数据源；需要时按世界黄金协会每季度的《黄金需求趋势》手工录入（一年 4 个数），同样只展示。

`docs/hengcang_gold_model_revision_v1_2.md` 保留作历史记录，其中宏观闸门部分以本节为准。

## 4. 持仓级投资逻辑、失效条件与事件日志

### 4.1 为什么消息不打分

把新闻自动打成分数噪音大、没有可回测的历史，被新闻牵着走是个人投资者最常见的亏法。财报要季度末后 1–4 个月才公布，等财报里的增长转负，价格往往已经跌了很多，体检熔断那时才触发，太晚。

v2 的做法：**事先写下「为什么持有」和「什么情况说明逻辑失效」，消息只用来对照这几条事实。**

### 4.2 规则（`src/domain/thesis.ts`、`src/server/thesis-service.ts`）

- **谁必须写**：单一个股和主题 ETF（`isSingleStock` / `isThematicEtf`）。它们的风险来自具体公司或行业的消息；宽基、债券、黄金由配置纪律管住，可写可不写。
- **投资逻辑**：一段话（≤ 2000 字）。**失效条件**：可验证的事实，建议 3–5 条，最多 8 条，每条 ≤ 200 字。
- **记录消息（NEWS）**：日期（不能晚于今天）+ 发生了什么 + 来源链接（只允许 http/https）+ 可选「对应哪条失效条件」。
  - 对应到某条 → 该条变为「已触发」，**该持仓暂停新增**，写一条 WARNING 信号。
  - 不对应 → 只记录。
- **写复核（REVIEW）**：
  - 对应已触发的条件 → 解除（回到有效），写一条 INFO 信号。
  - 不对应条件 → 定期复核。
- **季度复核**：自上次复核（没有则自写下逻辑起）满 90 天，提示「季度复核到期」。
- **已触发的条件锁定**：不能删除也不能改写，必须先写复核解除。否则改几个字就能绕过暂停。
- 删除持仓时，投资逻辑、失效条件和事件一并删除。

暂停新增是**持仓级**的：不改变所在资产桶的评分和状态。科技与成长可以仍是「可增配」，但新增资金不投给逻辑待复核的那只持仓。系统不执行交易，「暂停」是给人看的纪律提醒。

### 4.3 在哪里看到

- **持仓与风险**页：新增「投资逻辑」列（逻辑完好 / 季度复核到期 / 逻辑待复核：暂停新增 / 未写投资逻辑），点进 `/holdings/[id]`。
- **`/holdings/[id]`**：编辑投资逻辑和失效条件、记录消息、对已触发的条件写复核、定期复核、完整事件日志（含来源链接和记录时间）。
- **仪表盘**：「投资逻辑提醒」卡片常驻显示需要处理的持仓（暂停新增优先，其次复核到期，最后是集中持仓没写逻辑），处理完才消失。「最新信号」只显示最近 5 条，触发信号会被后来的评分信号挤掉，所以另做了常驻提醒。

### 4.4 数据与接口

迁移 `drizzle/0006_v2_holding_thesis.sql` 只新增三张表：

| 表 | 内容 |
|---|---|
| `holding_theses` | 每个持仓最多一份（`holding_id` 唯一），随持仓级联删除 |
| `thesis_breakers` | 失效条件：`status`（ACTIVE / TRIGGERED）、`triggered_at`、`triggered_by_event_id`、`last_reviewed_at` |
| `thesis_events` | 事件：`kind`（NEWS / REVIEW）、`occurred_on`、`summary`、`source_url`、`breaker_id`（条件删除时置空）、`recorded_at` |

接口：

- `GET /api/portfolio/holdings/:id/thesis`：逻辑、条件、事件、状态、是否需要写、是否到期。
- `PUT /api/portfolio/holdings/:id/thesis`：`{ thesis, breakers: [{ id?, description }] }`。带 id 的是修改 / 保留，不带 id 的是新增，没提交的会删除；改动或删除已触发的条件返回 409 `BREAKER_TRIGGERED`。
- `POST /api/portfolio/holdings/:id/thesis/events`：`{ kind: "NEWS", occurredOn, summary, sourceUrl?, breakerId? }` 或 `{ kind: "REVIEW", occurredOn, summary, breakerId? }`。还没写逻辑返回 409 `THESIS_NOT_FOUND`；条件不属于这份逻辑返回 422 `UNKNOWN_BREAKER`。

### 4.5 失效条件示例

- **港股互联网 ETF**：出现新的平台监管整顿；龙头营收连续两个季度负增长；回购明显收缩。
- **先导智能**：锂电设备行业资本开支同比下滑超过 30%；最大客户订单明显缩减；毛利率连续两个季度下滑。

写法要点：写可验证的事实（谁、什么指标、多大幅度），不写「感觉不好了」「跌太多了」这类价格描述。

## 5. 升级步骤

1. 停掉开发服务器和 `pnpm worker`，**先备份数据库**：`cp data/hengcang.db data/hengcang.before-v2.db`。
2. `git checkout main && git pull`，然后 `pnpm install`、`pnpm db:migrate`（依次执行 0004–0006）。
3. 运行一次 `pnpm data:refresh`（或页面「一键自动刷新评分」）：升级后第一次刷新会做财报增量刷新，并用 v6 规则重算评分。
4. 打开「设置」核对战略仓位应为 v2 默认值（海外权益 25%）。如果显示海外 0%，说明数据库里的目标改过，迁移没有覆盖，需要同样直接改库。
5. 在「持仓与风险」里给单一个股和主题 ETF 写投资逻辑和失效条件。

要回到 v1：停服务，`git checkout 8ef4160`（v2 合并前的 main），把备份文件拷回 `data/hengcang.db`。

## 6. 没做的和后续

- **按披露日历刷新财报**：现在是每周轮询，最多晚一周。
- **历史成分权重**：历史汇总用当前成分股，有幸存者偏差；应改用 `index_weight` 的历史快照。
- **换代理**：红利价值改中证红利（现为上证 50）；科技成长按真实持仓拆（港股互联网用恒生互联网类指数）；单只股票用它自己的财报做体检。在此之前，单股和港股互联网的风险主要靠 §4 的失效条件。
- **AI 新闻提醒（可选）**：每周读一遍持仓相关新闻和公告，只对照写好的失效条件标出「疑似触发」并附原文链接，由人确认后再记录。AI 只当提醒员，不出买卖信号。
- **验证**：体检和失效条件没有样本外回测，定位是纪律规则，不是收益来源；估值和趋势打分在样本外验证之前只宜做小幅偏离。
